# Writer

A desktop script editor. Footage is cut on this machine. Every key (ElevenLabs, Repack's Google Drive account, the YouTube proxy) lives on a Cloudflare relay, so none sits in the app and nobody installing Writer needs one. Scripts are written the way Repack writes them: Opus reads the whole transcript with Repack's cut-in guide and judgment calls (`src-tauri/guides/`), sends one plan of footage ranges and cut-in paragraphs, and the app checks it and cleans it up as Repack does (`src-tauri/src/tidy.rs`): breathing room at clip edges, edges that run on into fillers or stop mid-sentence moved to where the thought ends, and pauses cut to a beat only where the footage's sound is quiet (a gap holding speech the transcript missed stays), never leaving a piece under 1.2 s (a lone "The" plays as a blip: its pause stays instead). A compilation outside 6 to 7 Letter pages (counted as Repack counts them, `pages.rs`) or a FOIA cut under ten minutes goes back to Opus to bring in. It runs through the Claude Code login already on this Mac, so a build is paid by the Claude plan, not API calls. **Copy script** gives the text in Repack's Doc layout.

**Look.** Writer follows the spheceo kit (design/kit, Oct 23 2026): dark grey steps and hairlines, Inter shipped in `public/fonts`, red for the one main button and destructive answers, white focus rings and marks, no gold (the doc page's Google Docs highlights stay yellow, as the user chose). Signed out, the window is the sign-in: Continue with Google, or **Sign in with a code** on any other device (the accounts device grant, `account::sign_in_with_code`). The library's header follows Edit's Home: a wide search, Update (when there's one), New script and your avatar; under it, the sections (Footage, Compilations, Commentary, with counts) and style pills (Bodycam, Interrogation, Courtroom). Footage a commentary was written from stays inside it (a search still finds it). Your avatar opens the account menu (Manage account, Settings ⌘,, Logs, Report a problem, Sign out), each with its icon. What's under way (imports, Claude, the cloud's transfers) sits at the bottom left on every screen: its list opens by itself when new work starts, a click elsewhere closes it, and a click on it brings it back. Every dropdown is Writer's own (`Select` in `src/ui.tsx`), and menus open in a portal above everything. The disk image is the kit's install window (`scripts/make-dmg.sh`, `scripts/dmg/`), made after the app is signed and itself signed, notarised and stapled.

**How Writer reaches Claude**: through the Agent SDK for everyone since Oct 24 2026 (no longer a choice in Settings; *one answer*, `claude -p`, asks Opus for the whole plan in one reply and stays only for comparisons, `WRITER_ENGINE=cli`). The Agent SDK goes through Anthropic's Agent SDK, as Edit's agent does: `writer-agent` (`sidecar/`, a Bun program built by `scripts/build-agent.sh` and shipped beside Writer, signed with the hardened runtime and `scripts/writer-agent.entitlements`, notarised with the app) runs the user's own `claude` with nothing of their setup (no settings, CLAUDE.md, hooks, MCP servers or claude.ai connectors). There, a build is written in steps (`steps.rs`): Opus reads the same evidence and guides, then writes the plan with Writer's tools (add a section, replace or remove items by ID, review, finish), served over MCP on Writer's local server at `/mcp/<a random token per build>`. Each item is checked as it arrives, as the one-answer build checks it (`claude::item_clip`); review and finish check the whole plan as it will be saved; so no reply has to hold the whole plan, and a repair is a small call, not the plan again. Every other question (speakers, research, case files, clips, reviews, lessons) is one structured answer through the same SDK. Either way, every reply's stop reason is logged, and one cut off at its output limit says so plainly.

Every Repack format is covered, with Repack's own guides (`src-tauri/guides/`, kept word for word; Writer's own rules from the team's reviews are `guides/house.md`, given after them to FOIA cases and non-courtroom compilations, and checked where a count can find them by `house::text_flags` and `claude::team_flags`: full names, no addresses, outros of at most 45 words opening "In the end", cut-ins of 65, care words, the blow, narrated flashbacks, repeated transition openings, undated case openings, intro clips of 1–8 s that play again in the body, a case's first block of up to 2½ minutes) and wording (`src-tauri/src/formats.rs`): **Interrogation**, **FOIA** (one-run or two-split opening, a dated case opening, a 10-minute floor), **Courtroom** (a two-paragraph opening, pacing that relaxes in the second half), and **compilations** of 2 to 20 videos, one case each, in either style (a title that opens with "When" is a standard compilation, any other a hidden one). The format is picked in **New script**, before the import starts: Interrogation, Bodycam or Courtroom (a compilation offers the compilation types the person may use). It stays visible in the project header; the chat builds in that saved format.

Compilation inputs accept mixed labeled or raw YouTube, Google Drive file/folder and Google Docs script links in case order; `(reuse)` / `[reuse]` annotations work alongside `REUSE`. A Drive folder stays one case, with all its recordings retained and joined into a full-size master for Edit. Reused scripts keep their complete original fetched text (ranges, link targets and finished cut-in words) in `reuses[].scriptText`, separately from transition context; `script` is the full Doc URL. Composite folder parts retain their folder URL and expose `mediaSource` / `originalKey` for the master. See `docs/compilation-import-review.md` for the handoff contract and review steps.

Split and Video playback show source-timed subtitles, including spelling corrections, toggled with **CC**; cut-in cards and source audition hide them. In Video view, drag either end of the timeline overview to zoom into a portion, its middle to pan, or double-click to fit. Zoom buttons and pinch/⌘-wheel still work.

**New script** takes what Repack's form takes: an optional **article** about the case (read when the import starts, in place of searching); a compilation's videos **checked before anything downloads** (private, gone, live, age-restricted, over 10 hours), with **REUSE** before a link for a case the channel already covered (not imported: it takes only its transition, whose link goes into the Doc as a comment; **Reused cases** in Claude's panel can import its whole video later, joined onto the footage without encoding the rest again, transcribed alone, and read by Opus for its 5 to 8 strongest moments, which the build may open the video on as intro clips and nowhere else, `reuse.rs`); a compilation's case given as the **Google Doc of a script the channel already made** (always a reused case: nothing in it is rewritten; Writer reads the Doc for its title, the footage under Assets, which **Reused cases** can bring in, and its narration, which the transition is written to lead into, `reuse.rs`); several videos as **one Courtroom case** (a link's `t` kept as a hint to where the case starts); and a Drive case folder's **PDFs** (up to 20), which Haiku reads through Claude Code's Read tool for the case's facts (`casefiles.rs`). An incident report among them stands in for the web search.

**Brief** in New script takes a producer's brief pasted as it came (`brief.rs`): no two are laid out alike, so it's read roughly. The first line is the title; prose is the producer's notes, filed first among the research as "The producer's brief" (so no search runs, and **Research again** keeps them); each link is labelled by the line above it ending in a colon ("Part 3:", "Surveillance Footage:"), or by the words beside it, and given a role: **the case** (a hearing's "Part N", "Day N", trial, sentencing, or no label), **supporting footage** (surveillance, bodycam, an interrogation, a 911 call), **background** ("More on…", news, an explainer) or an **article** (any other web page, read for facts). Playlist and search parameters are dropped from YouTube links. The dialog shows how each link was read before anything downloads. One video imports as itself; several are one Courtroom case, joined hearing first by part, then supporting, then background, and each recording's label goes to the build beside its words ("the producer's brief: "Surveillance Footage": supporting footage, not the hearing: show it where the story reaches it…", `Script.labels`).

**Import from Trello** in New script lists the cards waiting on Repack's lists, read through the relay (which holds Repack's Trello key; nothing is written back) and parsed as Repack parses them (`trello.rs`): **Raw Channels** ("Script (Sphe)": a case a card, its first Drive folder or video as the footage, its first other web page as the article, its name as the title; a card labelled "Missing footage" is passed over) and **Compilations** ("Ready for script (comp)": the YouTube, Drive and script Doc links from "case N" onwards, a link reused when its line or the line above says so, or when it's under a heading that does, "Reused:"). A card a script already has the name of is hidden. A reused video followed by the earlier compilation's card and its number there ("https://trello.com/c/U0FrQAUk (Case 4)", on its line or the next) becomes `REUSE <video> <card> case 4`: the check and the import follow that card to the script Doc attached to it (or linked in its description or comments), cut the case out of it (the Doc's cases lie between its rules, or a paragraph each after its "These were…" line; the case whose clip links name the reused video wins over a wrong number) and give its narration, as written, to the build for the transition, as for a Doc given as the case (`reuse::read_earlier`). The Doc's reuse comment names that script for the editor. An earlier script that can't be found leaves a plain reused case, with the reason in the check and the log. Picking one fills the dialog, and a compilation's links are checked at once.

Once a script is built, a message to Claude **revises** it, as Repack's chat editor does: Opus (since Oct 24 2026, as for builds) answers with targeted edits (trim, take out or insert words, split, move, delete, add or rewrite a cut-in, fix a spelling, tighten pauses, fix edges), which Writer checks and applies all or none (`revise.rs`), with a repair turn for any it refuses. Asked to start over, Claude proposes it instead (`startOver`): the chat shows **Start the script over?** with Reject and Start over, and nothing is cleared until the producer accepts; then every clip and cut-in (or a commentary's draft) goes, the transcript, speakers, sources and research stay, and Versions keeps the script as it was (`reset_script_now`, `chat::ask_reset`). Web addresses in Claude's replies are links. A rewrite of narration already saved is a **proposal**, shown inline as removed and added words in Script view. An unscaled **Suggested changes** bar keeps **Follow up**, **Reject** and **Accept changes** visible above the page; accepting applies the proposals together only if the reviewed revision and original paragraphs still match. Reject keeps the saved wording. **Follow up** quotes the paragraph into chat. Chat follows new messages only while the reader is at the bottom, offers a jump to the latest, keeps unsent drafts per project, and has copy/retry actions and **Stop response** (stops the SDK sidecar or CLI process group). The conversation is kept with the script and goes back to Claude as context. Rebuilding from scratch is still there, behind a confirmation.

**Commentary** scripts are the other kind: an investigative video essay in the Internet Janitor's style (`src-tauri/guides/commentary.md`), written from sources instead of one case's footage. **New script → Commentary** takes a title and, optionally, links; the first link is the brief. In the project, **Add** brings in more: a Google Doc, a Drive text file or a web page (shared with "Anyone with the link", or with Repack's Drive account), a text file on this Mac, pasted text, or the transcript of footage already in Writer. Each source is the **brief** (the angle and the evidence to use), **evidence** (what the script quotes), or **style** (a past script, for the voice; never quoted). Opus reads them all in full and writes the montage, the intro, numbered chapters and the ending, with every clip naming its recording and times, editor notes, and a list of checks before recording. Writer refuses a quote its source doesn't hold, a link no source gives, a clip cited from a style example, and a timed transcript's clip whose times don't match the words. Each project has a **pacing** for its builds: **Channel** (the channel's own clip-led videos: a line of setup, then the person talks) or **Documentary** (narration-led like Turkey Tom's: about three quarters narration, a short clip about every 30 to 40 seconds, and footage shown under the voice as "Show:" notes). With Documentary pacing, Writer sends a plan back when its narration share or clip count is far off. Narration, editor notes and paragraphs can be edited or removed; clips stay as checked. **Copy script** gives the channel's Doc layout, with a "Total time = …min vo + … = …min" line (narration at 150 words a minute), the recordings with their links, the sources and the checks.

**Comments** (`src/comments.tsx`) are the review's notes, one set shown both here and on feedback.spheceo.com, which is the standard: the Feedback tab (and the Review dialog) shows them as the page does (avatar, name, time, unread dot, #n per version, the words or General, the intent tag, a suggestion's old and new words, the page's state line from Queued to Done in vN with the fix's summary on hover, threaded replies, a ⋯ menu), filtered (All, Open, Done, Unread, Writer's, by person) and sorted (in order of the work, newest first). Selecting words in a commentary's narration offers Comment: the note goes to the review on those words (`reviews:note` with the page's `{kind: "text", blockId, start, end, quote}` anchor, an intent, a suggestion's replacement), named in the text the version was shared with (`review-text.json`, kept at each share or read back from the version's snapshot). Replies go up signed with the person's name (`reviews:reply`), and Writer's own notes can be deleted (`reviews:deleteNote`). A comment's words are soft yellow, brighter while it or its card is hovered or open; clicking them opens the card. Unread is kept per Mac, as the page keeps it per browser.

**Feedback** teaches Claude what reviewers noted on a commentary, and tests that it learned it (`src-tauri/src/feedback.rs`, `src/feedback-panel.tsx`). Since Oct 24 2026 the feedback is the notes on the script's review page (feedback.spheceo.com, `reviews.rs`): each reviewer's note with the words it's on and its replies, a suggestion as its replacement, and notes left from the Feedback tab itself (posted to the review as Writer's, `reviews:note`, so they show on the page too). **Teach from these notes** reads them (polling the page first) and finds each in the script. Any item can be left out, and a highlight without a comment can be given a note saying what's wrong. **Run round** then:

1. Makes the answer key (first round only): Opus applies the feedback directly.
2. Writes the lesson (when there's none): Opus turns the feedback into a skill in general terms. A lesson that copies six words in a row from the script, or uses a name only the script has, is sent back; it would show the round the answers.
3. Tests it: a fresh Opus gets the sources, the script and the lesson, never the feedback, and is told only that a reviewer found problems of those kinds.
4. Grades the round: Opus compares what changed, paragraph by paragraph, with the feedback and the key. Each item is fixed, partly, missed or wrong, and every change nobody asked for is marked harmless or harmful. The match counts fixed as 1 and partly as a half.

**Improve the lesson** has Opus rewrite it from the last round's misses, or the producer edits it by hand; then run another round. **Keep the lesson** adds it to the lessons every commentary build reads, after the guide (kept in `lessons.json` beside `scripts/` and synced as `writer/lessons.json` on R2: every Mac merges its lessons with the cloud's by ID, and a lesson forgotten on one Mac is forgotten on all). **Use this round's script** makes a round's script the script, with what it didn't fix applied directly. Pulling again starts over. Everything else is under the script's `feedback/` folder, so it syncs with the script. A round takes about 15 minutes; the first, which also makes the key and the lesson, takes longer.

**Review** shares a script on a Repack link (`src-tauri/src/reviews.rs`, `src/review.tsx`): anyone with it reads the script and leaves notes under a name, no account. The page shows the script as blocks whose IDs stay as it is edited (`blocks.rs`): each footage clip (its range and words), each cut-in's narration, a commentary's montage, headings and paragraphs. **Share again** publishes the next version on the same link. While Writer runs it asks Repack for changed notes every 45 seconds; scripts with open notes get a count on their row and on the Review button. When a reviewer clicks **Ready for changes** on the review page, the one computer an admin chose on accounts.spheceo.com's Fixing page fixes them: Writer checks in there (`reviews:checkIn`, every 45 seconds, every 15 on the fixing computer, with the Mac's hashed hardware id from `machine.rs`, shared with Edit), takes the request (`reviews:takeFix`), claims the open notes (`reviews:claim`, so no note is fixed twice) and fixes them one at a time (`fixing.rs`), the page following along (`reviews:fixProgress`), then shares the next version, which the page offers to switch to: a footage script with the chat's edits, saved narration written straight in; a commentary with edits to the paragraphs the note is about, so nothing else can change. What each note changed is measured word by word on the blocks and sent back with Claude's summary; the page and Writer's Script view show it as green bands, and hovering one shows the reviewer's words, their name, Claude's summary and the version it lands in. A note Claude made no change for gets its reason as a reply and stays open; one a reviewer opens again is fixed again. Nothing is fixed by itself otherwise (the five-minute quiet timer and its switch went on Oct 24 2026); the Review dialog fixes the open notes now, by hand, on any computer. **Approve vN** marks the latest version done: the link takes no more notes, nothing is fixed by itself, and Repack deletes the other versions' review files (every note from every round stays; Writer's own version history is separate and untouched). An approval made on Repack's page is heard on the poll (`reviews:open`); the row and the Review button show "Approved vN". Sharing again starts the next version, unapproved; an approval can be taken back.

The review page (feedback.spheceo.com, spec v2) gets more than the text: each footage block's transcript just outside it (for "start earlier" / "end later"), where it plays in the preview and each word's timing, narration's read time at 150 words a minute, every block's running time, its `edit:` notes, an outline rail (opening, cases or recordings, ending; a commentary's sections), the format's target length, and the preview's key. Word timings move to a file of their own if the page's data would pass Repack's 512 KB. What a reviewer says exactly is done exactly, with no model in between: a suggestion's words replace the anchored ones (on a footage clip, as a respelling, word for word), a footage action cuts the chosen words or moves the clip's edge to the words chosen beside it, and a note for the editor becomes an `edit:` note as written. A note's intent limits what Claude may change: a question is only answered, a fact is checked and answered with its source (edited only if wrong), wording changes narration only and a cut footage only (a fix that strays is undone and the note stays open), FYI changes nothing. "Everywhere" carries the ask across the script.

**Make this v1** (the Review dialog, once a link is past v1; `POST /api/scripts/<id>/review/compress`): the script as it is now becomes the link's only version, v1, on the same link, through Repack's `reviews:compress` (allowed on the relay with `review.share`). The later versions leave the link, their files are deleted unless v1 still uses them, and every note moves onto v1. Writer's own version history is untouched. A commentary's page shows its montage under the Intro heading, as the team's Docs do.

**edit: notes** are for the video editor: asked for one ("add an edit note: a blue waveform for this 911 call"), Claude puts it on that footage clip's timestamp, or under a commentary paragraph's editor note, starting `edit:`. They show in purple beside the page, go into the Google Doc, sync with the script, and Edit's agent follows them in that section when the script is handed over. On a written commentary, a message now changes only the paragraphs it is about; **Rewrite the whole script** under the box writes it again from the sources.

**Clips → Find clips** searches YouTube for what a commentary brief asks for (`src-tauri/src/scout.rs`). Opus turns the brief into up to 30 moments the video needs, each with a few searches; yt-dlp runs them and Sonnet picks up to three likely videos a moment (the original stream or podcast first), and the brief's own YouTube links are always read. yt-dlp fetches each video's English captions, timed to the word, without the video; Sonnet reads them for the moments and copies their words, and Writer keeps only those whose words are in the captions near their times. Where a moment's point is what's on screen, Writer downloads just those seconds at 360p, tiles 12 frames into one image, and Sonnet says whether it shows what's wanted. Each video with a moment goes in as timed evidence holding its captions around each moment, so the next build can play its clips; a second search replaces those sources. The Clips tab lists them by the brief's chapters, with each video's link at the moment, the words, why it fits and the frames. A search takes 10 to 20 minutes; videos without English captions are passed over.

Before writing, a build:

- **Names the speakers** with Haiku through the Claude CLI, as Repack's speaker check does: "Name (Role)" only when a full name is stated, otherwise the role. It also runs right after transcription.

**Courtroom footage on YouTube is read from YouTube's own captions** (`captions.rs`), not heard: free, and minutes for a hearing of many hours. Only YouTube's English speech recognition counts (the `en-orig` track; a translation, or captions an uploader timed by line, don't), read with the person's YouTube sign-in when there is one; a transcript Edit already heard wins, and a video without captions is heard as before. A word has a start but no end, so it ends after the time it takes to say (60 ms a letter, 250 ms a digit: the 75th percentile of 89k words ElevenLabs timed in Writer's scripts) or at the next word, whichever comes first. YouTube marks a change of speaker with ">>" but never says who, so each ">>" opens a turn of its own. Measured on Oct 25 2026 against ElevenLabs on a 20-minute hearing (3,042 words matched): starts within 49 ms (110 ms for nine words in ten), ends 58 ms late (140 ms), where the next word's start would be 373 ms; 93% of the marks fall on a change of speaker, but they mark only about two thirds of them. The captions are kept as `captions.json`, never as the recording's `transcript.json`, so they're never handed to Edit as heard words.

Words from captions get **who says each line read from the conversation** (`turns.rs`), as Repack's line check reads them, in place of the watcher: Sonnet reads lines from across the footage with the case's names and the producer's notes and lists who speaks ("Name (Role)", or the role), then reads the transcript 120 lines at a time, four at once, each window a few lines into the last, and gives every line to someone, splits a line where a second person starts (quoting their first words), and respells a name YouTube misheard. Lines end at a turn, a pause of 1.5 s or 45 words. Each answer is kept under `turns/`, with the words as captioned (`turns/heard.json`), so **Retry unfinished speaker checks** reads only what wasn't answered.

Once a captioned script's build has chosen its clips, **its footage is heard exactly** (`exact.rs`): Scribe hears only those stretches (each clip with 3 s either side, neighbours joined, in pieces of one request each: about 25 minutes of a 9-hour hearing), so each word there takes Scribe's start, end and spelling (a short run each heard differently, word for word, takes Scribe's words; any other word sits between its neighbours, and every word keeps its ID). Sonnet then reads those stretches' lines, broken wherever Scribe heard the voice change, with the cast, and gives every line its person. The same plan is cut again on the exact times, and a piece with nothing above a fifth of the speech level of the minute around it is dropped. Footage cleared from this Mac is brought back first; if the hearing fails, the build keeps the captions' cut and its report says so. The stretches heard are kept in `Script.exact` (and what Scribe heard in `exact/`), so a revision hears only footage it newly plays; `POST /api/scripts/{id}/exact` does it for a script built before.

Right after transcription, every other import also **checks who speaks** by watching the footage, as Repack's and Edit's watcher does: Gemini (through the relay) sees and hears about four minutes at a time, eight stretches at once, and says who says each line and who each person is. Speech to text tells voices apart by sound alone, so this splits two detectives it heard as one and joins one person it heard as two; a guess changes nothing. Each person gets "Name (Role)" when the footage gives a full name, otherwise the role; then Haiku reads the corrected transcript for the suspects, the voices the footage didn't show, and a full name the title or transcript gives someone the footage only gave a role. Each stretch's answer is kept, so a retry doesn't pay twice (about $0.50 an hour of footage). Audio has nothing to watch, and a failure is a note on the script: the speakers stay as heard and Haiku names them as before.
- **Researches the case for free**, the way the sibling Edit app does: Haiku writes a few searches, Writer reads DuckDuckGo's plain HTML results and the pages on this Mac's own connection (no search API or key), and Sonnet keeps only the reports about this case with their facts (dates, places, names, charges, outcomes). They go to the builder as RESEARCH. **Research again** in the script looks once more. A failed search never stops a build. A compilation's cases are researched each on its own, side by side, from its own video's words, and each report is labelled with its video (`research::find`). Reading only the start of the transcript found reports about the first case alone.

**Google Doc** exports a script as Repack does (`apps/web/src/server/script-documents.ts`): a new Doc each time, made from a Word file Writer lays out (`src/doc-export.ts`, `src/docx.ts`) so Docs keeps its comments, in the "Writer scripts" folder of the account that owns Repack's script Docs, open to anyone with the link as an editor. It lists the footage under Assets (a compilation's or a Courtroom case's videos in order), and every timestamp links to its own video's moment where there is one and carries a comment (a footage script's first and last words; a commentary clip's quote and what to verify), narration words to blur get Repack's "Note to editor: Blur this" (a commentary's get "Censor", and its editor notes become comments), all signed GeniusScriptwriter10. **Export draft** makes the same Doc named "(DRAFT) …" without replacing the script's Doc; the dialog says when the script has changed since the last export, lists every export (from Drive, trashed ones marked), and reads back the comments people left on the latest Doc. A commentary can be rewritten with the open ones. The relay makes the Docs; their account's access never leaves it.

Editing has undo and redo (⌘Z, ⇧⌘Z), 30 steps, including undoing a fresh build. Edits show at once and save in turn; one refused because the script changed elsewhere takes the script from disk. **Versions** keeps every save (one author's edits within ten minutes merged), says who made each and what changed, and restores one. Clips move by dragging on the timeline; transcript words go in at the playhead as an insert edit, or at the start, and a word can be respelled. A Courtroom script's Script view drops the blank lines between blocks after the first, as Repack's does (the Doc runs them on in one paragraph). The heading can be rewritten in the Script view, and a comment written on a timestamp there goes into the Doc on that timestamp. Selecting narration offers **Add comment** and **Add to chat**: a comment keeps the selected words with it, syncs with the script, is read by the agent and exports on those words in the Doc; chat receives the quoted passage and its paragraph. The document toolbar shows **Fit page**, **Fit width** or the chosen percentage; comment cards stay at their normal size while the paper zooms. The Script view omits the Assets list, and **Google Doc** is in the project’s ⋯ menu. A build's outcome is kept beside the script, so one that ended unwatched, or one Writer closed on, says so.

Titles and thumbnails are not in this slice. Scripts live in Application Support and sync through the cloud.

**Archived** scripts (`src-tauri/src/archive.rs`): Repack's page can archive a script to free space; its server deletes the footage on R2 and marks the script's Convex row. When Writer hears it, it deletes the script's footage here too (originals, the preview, Drive recordings, reused cases' videos, heard audio) and keeps the script, its transcripts, the watcher's answers, versions, chat and every other small file, so it lists and reads, read-only, as Archived. A file from the Mac's disk outside Writer's folder is never touched. **Restore footage** (or Restore on Repack's page) downloads the footage again, from Edit's originals where they're back, else from the recordings' YouTube and Drive links, rebuilds the preview, puts it back in the footage registry and tells Repack (`writer:clearRestore`); the transcripts were kept, so nothing is heard again. What came from the Mac's disk can't come back and is listed as missing.

Every script is in the cloud with its footage: each recording goes to Edit's footage registry on import (Drive, YouTube, and a file from disk as `sha256:<hex>`). Scripts from before are brought in by a backfill, one at a time in the background (`cloud/backfill.json` says what it did); a YouTube video Writer downloaded before it used Edit's format is downloaded again in it first (at most one a quarter hour) and replaces Writer's older copy in the registry. Scripts titled "TEST…", commentaries and unfinished imports are passed over.

**Logs** (`src-tauri/src/log.rs`): Writer keeps a log in local time at `logs/writer.log` beside the scripts (`2026-10-22 21:40:20.462 INFO  [import] …`, rotated at about 8 MB with one older file kept). Areas: app, import, hear, agent, cloud, handoff, review, archive, backfill, export, tool. Long work tells its story naming the script: what it started on, each step with its size and time, and how it ended, with the cause when it failed; retries say which attempt, and any tool run slower than 2 s gets a line with its time. Tokens, keys and presigned URLs' signatures never go in. **Logs** (the button in the list's header, or ⇧⌘L anywhere) shows the last 2000 lines live, with search, a subsystem filter, All or Problems, Copy and Show in Finder (`GET /api/logs?since=<ms>`). Whatever is under way (imports, Claude's jobs, footage going to Edit, the cloud's transfers) shows on every screen in a panel at the bottom left, with its step, how far and a bar (`GET /api/activity`).

**Releases** (see AGENTS.md): `just nightly` ships a nightly, `just publish` a version (only when asked). GitHub Actions builds Writer.app for Apple Silicon and Intel, signs it with the Developer ID under the hardened runtime, notarises and staples the app and its disk image, and publishes it. Installed Writers update themselves from GitHub Releases (`update.rs`; the repo is public, no token): Update in the library's header (bottom right elsewhere) installs the newer build on the install's channel (Settings: Nightly, the default, or Stable; Writer looks every minute, reading the releases' Atom feed and asking GitHub's API only when it changes) and restarts. The build's name ("Writer nightly-2", "Writer v0.0.0") shows in Settings and the log.

## What a user installs

Only **Claude Code**, signed in (run `claude` once). Everything else comes with Writer or is fetched by it:

- **ffmpeg and ffprobe** are bundled inside the packaged app.
- **yt-dlp** is Writer's own copy: the official macOS build from yt-dlp's GitHub releases, checked against the release's SHA-256 list, unpacked in Application Support and replaced when a month old. YouTube extraction needs a JavaScript runtime, so every yt-dlp run is given one explicitly (`--js-runtimes` in `proc.rs`): the **qjs** bundled inside the app (QuickJS-ng, ~1 MB, fetched pinned and SHA-256-checked by `scripts/fetch-quickjs.sh`), else a deno, node, bun or quickjs installed on the Mac; a dev build with none of those fetches its own deno instead (`tools::ensure_js_runtime`).
- **HTTP** is Writer's own, so there is no curl, and no Infisical or Google key on the user's Mac.

An app opened from the Dock doesn't see a terminal's PATH, so Writer looks for each program itself: its own copy, the bundled one, then Homebrew, `~/.local/bin` and the system folders. Settings shows each one and where it came from.

## Run

```sh
bun install
just dev      # development: uses ffmpeg from Homebrew
just bundle   # the app to hand out, with ffmpeg and ffprobe inside
```

`just bundle` fetches static ffmpeg and ffprobe once (`scripts/fetch-ffmpeg.sh`, Martin Riedl's macOS builds linked from ffmpeg.org) into `src-tauri/binaries/`, refusing any that need a library macOS doesn't ship.

Footage comes from three places, as in Repack:

- **YouTube.** `yt-dlp` downloads on this Mac's own connection, which costs nothing. The relay's DataImpulse proxy (Repack's `PROXY_URL`) takes over only for a busy hour (4 or more YouTube downloads in the last hour, as a 20-video compilation would be) or when YouTube blocks this Mac; each try gets a fresh sticky exit. The proxy's login reaches the Mac only for the length of a download.
- **Google Drive.** A file link, or a folder link for a case: every video and audio recording in the folder and its subfolders, in name order, joined into one timeline as Repack joins them. Writer reads them as the Drive account Repack imports with: the relay holds that account's sign-in and hands Writer a one-hour access token. Share footage with that account. Downloads come straight from Google.
- **This Mac.** The file stays where it is.
- **A compilation.** 2 to 12 YouTube or Drive video links, one case each, joined in order with a "Video N" header per case.

Work runs side by side: up to 3 imports at once, 3 recordings downloading at once (Drive folders and compilations), and 4 transcription pieces heard at once (the relay allows 60 requests a minute per Mac, as Edit's does). Speaker checks watch up to 8 stretches at once. A gateway or connection timeout splits that stretch into smaller ones; each smaller answer and the split are kept for a retry too. Each parent stretch has a six-minute deadline and at most nine requests across retries and splits. The original transcription is saved before speaker corrections, so a retry keeps the same windows and cache keys. **Retry unfinished speaker checks**, in the warning or the project’s ⋯ menu, reuses completed answers and asks only for unfinished work. Opening, polling and reconnecting never start that retry. Progress starts with the saved checks already counted and says how many it reused.

Import completion refreshes the open script even though importing does not make an edit revision, including when the window returns after sleep, and shows an **Import finished** notice. Joined footage keeps a marker and title for each recording inside its timeline clips, including older imports whose footage is one long clip. The import screen separates transcription, visual speaker checks and naming the speakers. An unfinished visual check leaves the transcript and its audio-based speaker labels available; those labels may still combine or split voices incorrectly. Its saved status keeps unverified stretches visible until a check finishes.

When an import goes wrong it stops in a state you can act on, as in Repack:

- **Retry** carries on from where it stopped. The YouTube download (its `.part` too), each Drive recording, the preview and each transcribed piece are kept, so nothing downloads or is paid for twice. An import that stopped because Writer closed, or that hit a bug, is retried the same way.
- **Needs your choice** pauses an import on a question instead of failing it: some of a folder's recordings didn't come through (go on without them, retry them, or cancel); a folder holds more than an import takes (60 recordings, 20 hours, 10 hours or 30 GB a file: choose which); or no words were heard (open it without a transcript).
- A recording cut short (an interrupted upload) imports what it holds, and the script says so. One that downloads short is fetched again once from where it stopped, then dropped so a retry starts it clean.
- A YouTube bot check or dropped connection with nothing downloaded yet gets one more try, on a fresh proxy exit when there is one.
- Transcription retries only what can't have been billed: the relay unreachable, or busy (after 30 s, then 60 s). Refusals (no credit, a wrong token) say what the relay said and stop.
- Claude busy or overloaded gets one more try a minute later; a plan it sends wrong, or no plan, gets up to two repair turns on the same session. Nothing is saved to the script until a plan passes.
- Settings checks the setup: Claude Code signed in, ffmpeg and ffprobe, Writer's yt-dlp, and the relay with transcription, Drive and the proxy.

Every import makes a 480p preview (a joined folder's footage is that preview). When there are several recordings, each one's piece of the preview is encoded in its download's lane as soon as it lands, while the rest still come down, and the pieces are then copied end to end in seconds (`import::encode_piece`, `media::append`). A missing or mismatched piece means the whole preview is encoded, as before. Titles the link check read are reused by the import instead of asked for again and is transcribed through the relay. The editors play it as Repack plays its footage, never waiting on a download: `preview://localhost/<id>` (`src-tauri/src/stream.rs`) answers each range from the file on this Mac when it's here, otherwise from the cloud's copy through a presigned URL (kept, and asked again after 40 minutes), from 2 MB blocks kept in memory (96 MB) with the next four fetched alongside, since WebKit reads a video's index a few bytes at a time (a long compilation's is 19 MB) and wants every range with an end answered in full (open-ended ones get at most 4 MB); the script's kind is checked once per change of its script.json, not on every range (`can::require_id`). A preview played from the cloud is brought down behind it (`stream::keep_here`), so a cut's jumps around the footage turn instant once it's here. The local API's `/api/scripts/<id>/proxy` does the same. Previews are made with the index first (`+faststart`), so playing starts after the first range and a jump is one more. So a sync never downloads footage: a Mac's first sync brings each script's small files (script, transcript, peaks, chat, versions) and leaves its preview and originals in the cloud (`cloud.rs` pull, recorded in `cloud/storage.json` as cleared footage is), and the list fills in at once; only joining reused cases onto a preview brings it down (`storage::fetch_preview`).

`just dev` listens on this Mac only (127.0.0.1:1420), since the page proxies the whole API. To open it from another machine on the tailnet, run `tailscale serve 1420` here. The Writer window must stay open on this Mac, since it serves the API that Vite proxies; port 1421 itself only listens on localhost, and answers only its own address and the dev page. Opening a file from that browser takes a path on this Mac. The file dialog only runs in the Writer window.

Builds and imports run on this Mac, not in the browser. A build is a background job the page checks every few seconds, so a dropped connection, a sleeping laptop or a reload does not lose it, and the open script is in the URL. Over plain `http` the browser has no Clipboard API; **Copy script** falls back to the older copy command.

## Relay

`relay/` holds Writer's keys. Everything but `/health` needs a signed-in person's token, with the route's permission (`relay/src/auth.ts`):

- `POST /v1/transcribe` forwards Opus audio to ElevenLabs Scribe v2 with Edit's parameters, the case's names as `keyterm`s. It caps bursts and a day's audio per IP and across everyone (~20 hours, as Edit's). Byte caps stand in for duration; they are not a hard dollar cap.
- `GET /v1/drive/token` gives a one-hour access token for Repack's Drive account. The refresh token stays on the relay.
- `GET /v1/proxy` gives the DataImpulse proxy for YouTube downloads.
- `POST /v1/watch` sends a few minutes of footage to Gemini 3.8 Flash through the Vercel AI Gateway (the relay picks the model; 40 a minute per IP).
- `POST /v1/docs/export`, `GET /v1/docs/exports` and `GET /v1/docs/comments` make a script's Docs, list them and read their comments, as the account that owns Repack's script Docs. Only Docs in its "Writer scripts" folder marked with the script are listed or read.
- `POST /v1/cloud/*` is the cloud, as Edit's relay has it: presigned R2 URLs for keys under `writer/` only, and calls to Convex functions named `writer:` only, with Convex's service token added (`relay/src/cloud.ts`).

**Who may use it.** People sign in to Writer with Google at `accounts.spheceo.com`, where admins add them and tick what they may use. Writer opens the browser on first launch (RFC 8252: a listener on `127.0.0.1:<free port>/callback`, `/app/authorize` with PKCE and `state`, the code traded at `/app/token`; `src-tauri/src/account.rs`), keeps the refresh token in the Keychain (a dev build: `account-dev.json`, 0600, so rebuilds don't ask for Keychain access), renews the hour-long access token quietly, and sends it on every relay call. Settings shows "Signed in as …" and Sign out (`/app/revoke`). The relay checks the token's signature against the site's JWKS (cached ten minutes, refetched on an unknown `kid`), `iss`, `aud: "writer"` and `exp`, then `use` (or `admin`): every route needs only that. Bursts and the daily audio allowance are counted per person. What kinds of work someone may do is up to admins too: Writer publishes them at `/.well-known/spheceo-app.json` on the relay (`relay/src/manifest.ts`: interrogation, interrogation compilations, FOIA, bodycam (FOIA) compilations, courtroom, courtroom compilations, commentary, share for review, teach from feedback), and enforces them itself (`src-tauri/src/can.rs`, `src/can.ts`), from the token's `perms`. A script of a kind someone can't write is hidden from them (list, search, sources, opening it, any agent work); New script and the editor's format picker offer only what they may write, a new import starts as the first format they may. A bodycam compilation (since Oct 24 2026) gets Repack's compilation guide and its FOIA guide, as Repack gives a compilation in its FOIA workspace, with the compilation's shape, length and writing sequence. Review links, approving, fixing notes (by hand or on Ready for changes) and Docs export need `review.share`; the Feedback tab and lessons need `review.lessons`; leaving a review comment stays open to everyone. Writer keeps the last person's grants in `account-person.json` (no secret), so the library is right before the first renewal and offline. Each script records who started it (`createdBy`: their id, name, email and Google photo): Writer stamps the signed-in person on a new script, and the relay stamps the verified sign-in onto the script's first `writer:commitScript` (`actor`; Convex keeps it on create only, and the cloud's wins over the body's when pulled). `STAMP_CREATOR` in `relay/wrangler.toml` turns it off ("0") if Convex ever stops taking `actor`. Their photo sits on the script in the list and the editor's header ("Started by …"), fetched once into `avatars/` (`avatar.rs`) since the window loads no remote images; their initials if there's none; nothing on older scripts. Each request is logged with who made it (their id and email's first part, never the token). Signed out, Writer can't use the relay at all: the sign-in window stays until someone signs in. The team-wide token older Writers had built in (`CLIENT_TOKEN` / `WRITER_RELAY_TOKEN`) was retired on 2026-10-23; the relay refuses it, telling those builds to update and sign in.

To try it all on one Mac, `relay/test/accounts-stub.ts` stands in for the accounts site (its own keys; `STUB_PERMS`, `STUB_TTL`, `STUB_DENY`), with `wrangler dev --var ACCOUNTS_URL:http://127.0.0.1:8788` and a dev Writer started with `WRITER_ACCOUNTS_URL=http://127.0.0.1:8788` (debug builds only) and its relay URL set to the local worker.

**Its secrets** live in Infisical, Repack's project, `dev`, folder `/writer-relay`: references to the canonical values at the root (`CONVEX_URL` is `NEXT_PUBLIC_CONVEX_URL`, the Docs client is the Drive client). The ElevenLabs key is the exception: `ELEVENLABS_API_KEY` lives only in the Worker (set once with `wrangler secret put`), and the script refuses to touch it. `just relay-secrets` puts them on the Worker with `wrangler secret put`, through pipes, printing none (`--dry-run` lists them; name keys to put only those). Then:

```sh
cd relay && bunx wrangler deploy
```

The Drive token and the proxy hand out a working credential (an hour of Repack's Drive account; the DataImpulse login), so `drive` and `proxy` are worth giving with care. The app looks for `https://writer-relay.sphe-g-personal.workers.dev` until you change that URL.

Footage is heard as Edit hears it, one system for both apps (`hearing.rs`, a port of Edit's `transcribe.ts`): a recording up to 90 s in one go; a longer one twice at once, in 40 s pieces (4 s either side) for its words and times, and whole for who speaks, the two lined up by what they say. A joined case is heard recording by recording, from each one's own file (joined cases now keep their recordings). Every request listens for the case's names (`names.rs`, Edit's `names.ts`: Gemini lists the people and places its articles, case files and narration give, each word checked against them, surnames on their own too); case PDFs are read before the footage is heard, so their names count. What's heard is kept as it comes in, so a retry never pays twice; each recording's transcript is `transcript/<recording>/transcript.json` in Edit's format.

**The handoff to Edit** (`handoff.rs`): after every import, each recording goes to Edit's footage registry (`edit:putMedia`, under `drive:<id>`, `youtube:<id>` or `sha256:<hex>`) with its original on R2 under `edit/originals/`, and its words to `edit/analysis/<source>/transcript.json`; before hearing a recording, Writer reads Edit's transcript of it if there is one. A script from before Writer heard footage Edit's way shares its footage (the backfill) but not its words: Edit hears those itself, once. What is in Edit's originals (`edit-shared.json`) leaves Writer's own sync. YouTube videos are downloaded in Edit's format (H.264 up to 1080p), so both apps share one file. Edit's New project dialog lists every built script from the cloud; there is no step to send one.

## Cloud

Every script is in the cloud and on every Mac running Writer, as Edit's projects are. Each script's body (`script.json`) and files (the proxy, the original, transcript pieces, sources, research, the watcher's answers) sit on Cloudflare R2 under `writer/scripts/<id>/` in Repack's bucket; Convex (Repack's deployment, `apps/web/convex/writer.ts` in the Repack repo, published with Repack's `db:push`) keeps the index: each script's rev, body and files. Writer only talks to the relay.

`src-tauri/src/cloud.rs` runs in the background whenever Writer has its relay token. Saves land on disk as always; a few seconds after a script is still, its changed files go up, then a new body, then `writer:commitScript` naming the rev it began from. Every 30 seconds it pulls what other Macs pushed. A commit another Mac overtook is refused, and this Mac's version is kept as "<title> (conflicted copy)" before the cloud's is taken. Scripts still importing or being written by Claude wait until they are done. Deleting a script marks it deleted in Convex (so every Mac removes it) and deletes its files from R2. What this Mac knows is in `cloud/ledger.json` beside `scripts/`; deletions waiting for the connection in `cloud/deleted.json`. The lists and editors show the state (synced, uploading, offline), and an open script follows changes that come down.

The bodies are on R2, not in Convex's file storage: Edit's nightly sweep deletes Convex-stored JSON that no Edit project uses. Keep Writer's keys under `writer/`: Repack's own cleanup deletes unrecorded files under `repack/`.
